# AnythingLLM chat routing

Tracked in [#48](https://github.com/ClawNexAi/clawnex/issues/48). The first supported contract is AnythingLLM 1.16.1's developer API.

Register a host-installed instance under Configuration → Fleet & Routing → Fleet Connectors. Supply its localhost origin and a developer API key. AnythingLLM must run on the same host as ClawNex. Inference connects directly to `http://127.0.0.1:4001/v1` (or the configured `LITELLM_PORT`), following the existing local-agent routing architecture. There is no connector-specific inference endpoint or dashboard relay.

Registration reads configuration only. Under AnythingLLM Routing, default chat is selected initially. Choose an upstream model already configured and tested in ClawNex. Workspace overrides are opt-in. Workspaces without an explicit provider follow the default and have no misleading independent routing toggle. Refresh discovers new workspaces, preserving selections by stable workspace ID. Review lists affected inherited workspaces as well as explicit changes.

The adapter reserves an unused AnythingLLM LiteLLM connection and switches selected chat routes to it. Existing Generic OpenAI/OpenRouter/etc. endpoints and credentials are untouched. An existing LiteLLM connection is never taken over. Selected workspace models can differ; the reserved default model is fixed in this first version. Restore a managed workspace before changing its model. Router-managed workspaces are unsupported because changing their provider can clear router configuration. Agent overrides and embeddings remain outside chat-routing coverage.

Management requests use the supported `/api/v1/system`, `/api/v1/workspaces`, `/api/v1/system/update-env`, and `/api/v1/workspace/:slug/update` endpoints. HTTP 200 does not imply success: application errors and readback mismatches fail the operation. AnythingLLM does not offer an atomic compare-and-set across these APIs. ClawNex re-reads before writes, retains recovery ownership before mutation, and refuses observed operator conflicts; concurrent external edits cannot be made fully transactional.

Review plans are server-stored, expire after five minutes, and bind current configuration plus selections. Apply and restore use a cross-process lease. Partial failures retain recovery data and require another review. Restore changes only still-owned provider/model fields. It retains the reserved LiteLLM connection for reuse, since the API masks credentials and cannot prove whether an operator changed a saved key.

The management key is encrypted with AES-256-GCM, an instance-ID AAD, and a purpose-derived key from `EVIDENCE_ENCRYPTION_KEY`. Preserve that key with the database during deployment/recovery. No key is returned to the dashboard. The inference provider uses the local proxy's configured `LITELLM_MASTER_KEY`, or a placeholder when proxy authentication is not configured. No separate relay key, relay-specific timeout, rate limit, or request filter exists. LiteLLM continues to enforce Shield policy and report telemetry.

Verify checks saved route settings and the loaded model deployments. It reports `configured`, never `verified` traffic. AnythingLLM's built-in LiteLLM provider does not attach ClawNex's signed instance header; shared-model traffic must not be presented as exact-instance evidence. Confirm real requests in Traffic Monitor. Agent overrides and embeddings remain outside chat-routing coverage. Historical relay events remain historical and do not establish current direct-route attribution.

For an existing relay-based registration, first move AnythingLLM onto the host with a consistent storage backup. Then run `tsx scripts/migrate-anythingllm-direct.ts <connector-uuid> --apply` with the deployment environment loaded. This explicit migration checks the existing managed fields, updates the provider to the local proxy, preserves original-provider recovery records, and removes the retired relay credential. The legacy `relay_origin` database column remains empty for schema compatibility; it is no longer a runtime endpoint.

Run `npx tsx scripts/verify-anythingllm-routing.ts`, `npx tsx scripts/verify-routing-evidence.ts`, `npx tsx scripts/verify-routing-ingest-evidence.ts`, and `python3 scripts/verify-routing-logger-evidence.py`. For an isolated browser fixture, run `npx tsx scripts/routing-ui-fixture.ts --anythingllm` (or add `--production` after building).
